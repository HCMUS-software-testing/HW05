## 1. Nguyên tắc Cốt lõi & Chiến lược AI-First Human Review

Dự án áp dụng chặt chẽ mô hình **AI-First & Human Review** qua từng checkpoint kỹ thuật có thể kiểm chứng:

```
[ AI Assistant ]  ──(Sinh Test Plans / Logs / Đề xuất)──►  [ Human Review Checkpoint ]
                                                                     │
                                                       (Kiểm tra, bắt lỗi ảo giác,
                                                        tinh chỉnh tham số thực tế)
                                                                     │
                                                                     ▼
                                                      [ Artifacts & Evidence Chuẩn ]
```

1. **AI Generation (Có kiểm soát)**: Hướng dẫn AI từng bước (step-by-step prompts) để sinh cấu hình JMeter `.jmx` (chuẩn Custom Thread Groups), tạo dữ liệu CSV test, phân tích log `.jtl` và đề xuất kiến trúc CI/CD.
2. **Human Review & Săn lỗi Ảo giác (Task 2)**: Sử dụng công cụ đo đạc Ground Truth để đối chiếu, phát hiện ít nhất 3-4 lỗi diễn giải sai của AI trong raw `.jtl` logs và phân loại tính khả thi các đề xuất tối ưu.
3. **Agent Skill Tự động hóa (Tiêu chí 6)**: Xây dựng một Agent Skill độc lập (`performance-testing-agent`) có khả năng tự động hóa việc seed dữ liệu test accounts, tạo test plan, chạy test headless, phân tích log và tự động cập nhật nhật ký `ai-audit-report.md`.

## 2. Phân rã Workflow & Bảng Mapping API Endpoints

Workflow của Thành viên 1 bao phủ đầy đủ cả 3 nhóm endpoint theo đúng quy định của đề bài:

| STT | Bước Workflow | Endpoint & Method | Nhóm Endpoint | Dữ liệu đầu vào (Data-driven) | Kỳ vọng (Expected Response) | Assertion & Trích xuất dữ liệu |
|---|---|---|---|---|---|---|
| 1 | Đăng nhập tài khoản | `POST /api/login` | **Auth-heavy** | `credentials.csv` (50 test accounts) | `200 OK`, JSON chứa JWT `token` và thông tin `user` | **JSON Extractor**: lấy `token` vào biến `${token}`. **Assertion**: Response code = 200, body chứa `"token"`. |
| 2 | Tìm kiếm sản phẩm | `GET /api/products?search=${search_term}` | **Read-heavy** | `products.csv` (`search_term`) | `200 OK`, danh sách mảng JSON các sản phẩm khớp từ khóa | **Assertion**: Response code = 200, Content-Type = `application/json`. |

## 4. Lộ trình Triển khai Chi tiết (8 Giai đoạn)

### Phase 1: Chuẩn bị Môi trường, Cài đặt JMeter Plugins & Seed Dữ liệu
1. **Khởi tạo Backend SUT**:
   - Chạy `npm install` trong `eshop-sut/backend`.
   - Seed database bằng `node database.js` (tạo bảng `users`, `products`, `orders`, `categories`, `coupons`).
   - Khởi động server: `node server.js` (lắng nghe tại `http://localhost:3000`).
2. **Cài đặt & Cấu hình JMeter Portable + Plugins Manager**:
   - Tải và giải nén Apache JMeter 5.6.3 vào `tools/apache-jmeter-5.6.3/`.
   - Tải `jmeter-plugins-manager-1.10.jar` vào thư mục `lib/ext/`.
   - Cài đặt plugin chuyên dụng:
     - `jpgc-casutg` (Custom Thread Groups): Cung cấp **Stepping Thread Group** và **Ultimate Thread Group**.
     - `jpgc-perfmon` (Servers Performance Monitoring).
   - **Tối ưu JVM Heap**: Sửa file `jmeter.bat` với cấu hình: `set HEAP=-Xms1g -Xmx4g` nhằm đảm bảo JMeter không bị nghẽn Garbage Collection khi tải lên đến 350+ threads.
3. **Mở rộng & Seed 50 Tài khoản Test Thực tế**:
   - Sử dụng script `seed_test_accounts.py` để tự động tạo 50 tài khoản (`loadtest_user01@eshop.com` đến `loadtest_user50@eshop.com`, mật khẩu `Test1234!`) trực tiếp vào cơ sở dữ liệu SQLite của SUT.
   - Xuất file dữ liệu `submissions/23127205/data/credentials.csv`.
   - *Lợi ích*: Phân tán tải xác thực cho Auth-heavy endpoint, cô lập rủi ro account lockout và tránh tắc nghẽn database lock trên 1 dòng đơn lẻ.
4. **Smoke Test Xác minh**:
   - Test nhanh 5 API endpoint để đảm bảo SUT phản hồi đúng trước khi test tải.

### Phase 2: Xây dựng Custom Agent Skill (`performance-testing-agent`)
1. Tạo thư mục `.agents/skills/performance-testing-agent/`.
2. Viết file `SKILL.md` định nghĩa workflow kiểm thử hiệu năng tái sử dụng:
   - Quy chuẩn thiết kế kịch bản (Standard, Stepping, Ultimate, Soak).
   - Quy tắc chọn timer (Gaussian Think-time), ramp-up, và stepping profiles.
   - Cơ chế thu thập log và tự động đối chiếu ground truth.
3. Xây dựng bộ công cụ Python hỗ trợ:
   - `seed_test_accounts.py`: Tạo pool 50-100 tài khoản test chuẩn hóa.
   - `jmx_generator.py`: Tự động tạo cây XML Test Plan chuẩn cho JMeter hỗ trợ đầy đủ Standard Thread Group, Stepping Thread Group và Ultimate Thread Group.
   - `jtl_parser.py`: Đọc file raw `.jtl` và tính toán chính xác 100%: Total Samples, Error Rate (%), Average RT, Min, Max, Median (p50), p90, p95, p99, Throughput (req/sec).
   - `reset_lockout.py`: Tự động xóa cờ `locked_until` và `login_attempts` trong SQLite giữa các lần chạy Stress/Spike.
   - `audit_logger.py`: Tự động format và ghi nhật ký AI Audit theo chuẩn bài tập.

### Phase 3: Thiết kế Dữ liệu & Sinh Test Plans Nâng cao bằng AI
1. **Chuẩn bị Dữ liệu Data-Driven (CSV)**:
   - `credentials.csv`: 50 tài khoản test (`loadtest_user01..50@eshop.com,Test1234!`).
   - `products.csv`: Danh mục từ khóa (`iPhone,1`, `Samsung,2`, `MacBook,3`, `AirPods,4`, `Keychron,5`).
   - `orders.csv`: Dữ liệu giao hàng (`"227 Nguyen Van Cu, Q5, TP.HCM",30000000`).
   - **Cấu hình CSV Data Set Config**:
     - Sharing mode: `All threads` (mỗi VU lấy tuần tự/phân tán 1 tài khoản).
     - Recycle on EOF: `True`, Stop thread on EOF: `False` (cho phép tái sử dụng an toàn khi tổng số request > 50).
2. **Bảng Cấu hình Kỹ thuật Chi tiết cho 3 Scenarios**:

| Scenario | Loại Thread Group | Cấu hình Thông số Kỹ thuật | Mục đích & Đặc điểm Kỹ thuật | Listener Bắt buộc |
|---|---|---|---|---|
| **Load Test** | **Standard Thread Group** | • Number of Threads: **50 VUs**<br>• Ramp-up: **60s**<br>• Loop Count: **10** (Tổng 500 iter, 2500 req)<br>• Timer: Gaussian Random Timer (1500ms ± 500ms) | Đo throughput và latency ổn định trong điều kiện vận hành bình thường. | **Summary Report** |
| **Stress Test** | **Stepping Thread Group** (`jpgc-casutg`) | • Start: **50 threads**<br>• Add **50 threads** mỗi **30s**<br>• Ramp-up: **10s** mỗi bậc<br>• Hold: **30s** mỗi bậc<br>• Max: **250 threads** | Tạo đường tải bậc thang (staircase) để xác định chính xác **Breaking Point** (ngưỡng bão hòa tài nguyên và suy giảm RPS). | **Aggregate Report** |
| **Spike Test** | **Ultimate Thread Group** (`jpgc-casutg`) | • Start Threads: **350 threads**<br>• Initial Delay: **0s**<br>• Startup Time: **10s** (Bơm tải cực nhanh)<br>• Hold Load: **30s** (Duy trì đỉnh tải)<br>• Shutdown Time: **10s** (Ramp-down có kiểm soát) | Mô phỏng đợt tăng tải đột ngột (flash sale) và quan sát khả năng tự phục hồi của SUT sau đỉnh tải (tránh ngắt đột ngột gây lỗi giả). | **View Results Tree** |

### Phase 4: Human Review Checkpoint 1 (Rà soát & Sửa đổi Test Plan)
Lập bảng đánh giá phản biện test plan ban đầu của AI:
- **Lỗi 1 (Token Passing)**: AI quên gắn Bearer Token trích xuất từ `/api/login` vào các request sau (`/api/cart`, `/api/checkout`), dẫn đến lỗi 401 Unauthorized toàn bộ.
  - *Human fix*: Thêm `JSON PostProcessor` với expression `$.token` và thêm `HTTP Header Manager` chứa `Authorization: Bearer ${token}`.
- **Lỗi 2 (Think-time phi thực tế)**: AI đặt Think-time = 0ms, làm giả lập hành vi người dùng như một cuộc tấn công DoS thay vì luồng duyệt web thực tế.
  - *Human fix*: Thêm `Gaussian Random Timer` mô phỏng độ trễ suy nghĩ 1-2 giây của người dùng thật.
- **Lỗi 3 (Weak Assertions)**: AI chỉ assert HTTP Status 200 mà không kiểm tra cấu trúc JSON trả về (SUT trả 200 nhưng body chứa error).
  - *Human fix*: Thêm JSON/Text Response Assertions kiểm tra sự tồn tại của trường dữ liệu mong muốn.
- **Lỗi 4 (Thiếu Ramp-down và Step)**: AI ban đầu sinh Stress test tuyến tính đơn giản và Spike dừng đột ngột (hard stop).
  - *Human fix*: Chuyển sang Stepping Thread Group và Ultimate Thread Group của plugin `jpgc-casutg` có đầy đủ chu kỳ ramp-up, hold và ramp-down.
- **Lỗi 5 (Account Lockout)**: AI dùng 1 account duy nhất dẫn tới nguy cơ khóa tài khoản diện rộng.
  - *Human fix*: Mở rộng pool 50 tài khoản độc lập và chuẩn bị tool `reset_lockout.py`.

### Phase 5: Thực thi Test, Thu thập Raw Logs & Đo Ngưỡng Endurance
1. **Chạy Test bằng CLI (Headless)**:
   ```bash
   jmeter -n -t test-plans/23127205_Load_20260829.jmx -l results/load/raw.jtl -e -o results/load/html-report
   jmeter -n -t test-plans/23127205_Stress_20260829.jmx -l results/stress/raw.jtl -e -o results/stress/html-report
   jmeter -n -t test-plans/23127205_Spike_20260829.jmx -l results/spike/raw.jtl -e -o results/spike/html-report
   ```
2. **Thực hiện Endurance/Soak Test (10-15 phút)**:
   - Duy trì tải ổn định (30-40 VUs liên tục trong 12-15 phút).
   - Đo lường: Maximum Stable Throughput (RPS), p95 Response Time, Tỷ lệ lỗi (Error Rate), Memory Ceiling (Node.js heap size) và mức sử dụng CPU.
3. **Thu thập Bằng chứng**:
   - Chụp ảnh cấu hình phần cứng qua `dxdiag` và bảng thông số chi tiết (CPU, RAM, OS, Hostname).
   - Chụp ảnh màn hình chạy JMeter đồng thời với Task Manager/Resource Monitor hiển thị tiến trình `node.exe`.

### Phase 6: Phân tích AI & Săn lỗi Diễn giải sai (Misinterpretation Hunt - Task 2)
1. **Prompt cho AI**: Đưa mẫu log và yêu cầu AI phân tích hiệu năng, xác định bottleneck.
2. **Human Verification (Đối chiếu Ground Truth)**:
   - Dùng `jtl_parser.py` đọc trực tiếp raw `.jtl` file.
   - Chỉ ra ít nhất 3-4 điểm AI đọc sai / bịa số liệu:
     - AI nhầm lẫn Average Response Time với p95/p99.
     - AI suy diễn sai nguyên nhân lỗi kết nối dưới đỉnh Spike thành lỗi cú pháp code.
     - AI tính toán Throughput sai do bỏ qua thời gian ramp-up/ramp-down.
3. **Phân loại Đề xuất Tối ưu của AI**:
   - **Khả thi (Feasible)**:
     - Bật SQLite WAL mode (`PRAGMA journal_mode = WAL;`): Cho phép concurrent readers và non-blocking single writer.
     - Tạo Index cho cột `products(name)`: Tăng tốc độ query tìm kiếm `LIKE '%search%'`.
     - Connection Pooling và Prepared Statement Cache trong Node.js.
   - **Ảo giác / Không khả thi (Hallucinated / Inapplicable)**:
     - Gợi ý cấu hình Redis Cluster hay Kafka Broker cho môi trường SQLite single-process.

### Phase 7: Đề xuất Continuous Performance Testing (Task 3 - G9.6 Disrupt)
1. **Xây dựng Kiến trúc Pipeline CI/CD**:
   - **Trigger**: Webhook kích hoạt khi có Pull Request hoặc Commit vào nhánh `main` liên quan đến `backend/` hoặc schema database.
   - **Smart Test Selection**: Chạy Smoke Load Test (5 phút) trên môi trường Staging/Ephemeral Container.
   - **Baseline Comparison & Regression Flagging**: So sánh `p95` và `Error Rate` với Baseline commit trước đó. Nếu `p95` thoái hóa > 15% hoặc Error Rate > 1%, tự động đánh dấu Fail PR và gửi alert cảnh báo.
2. **Sơ đồ Mermaid Flowchart**: Vẽ biểu đồ trực quan toàn bộ quy trình CI/CD.
3. **Phân tích Trade-offs**:
   - *Chi phí (Cost)*: Tiêu tốn CPU credit của GitHub Actions runner.
   - *Thời gian (Runtime)*: Làm tăng thời gian chờ merge PR (thêm 5-10 phút).
   - *Nhiễu môi trường (Flakiness & False Alarms)*: Môi trường chia sẻ (shared runner) có thể làm biến động latency -> giải pháp: thiết lập ngưỡng dung sai (tolerance threshold) hoặc dùng dedicated performance runner.
